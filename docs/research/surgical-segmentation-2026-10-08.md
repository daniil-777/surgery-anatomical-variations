# Surgical photograph segmentation for material transfer

Research checked **2026-10-08**. Scope: segment visible tissue in surgical RGB photographs, associate a reviewed region with a Viscera organ, and use the region for appearance authoring. These notes do not establish clinical organ recognition, segmentation performance on the user's images, or recovered optical/mechanical tissue properties.

## Decision

Use **interactive, reviewed masks as the shipping contract**, with an explicit organ target. Keep segmentation independent from material extraction so that uploaded masks, manual corrections, local classical segmentation, and optional foundation-model backends all produce the same mask contract.

For a pretrained local upgrade, **SAM 2.1 with positive/negative points and a box is the lowest-friction defensible default**: weights are directly available, image APIs are established, and licensing is explicit. For text-driven semantics, surgical adaptation of SAM 3 remains a research option. **Correction from the subsequent whole-body investigation:** Surgical SAM 3.1 does publish weights; this is distinct from the SurgSAM3 LoRA release below. Its reported anatomy results still do not justify trusting arbitrary automatic organ labels. This is an engineering choice based on deployability and evidence, not a universal accuracy ranking.

The public Surgical SAM 3.1 repository at revision `1c0c2ed55d46a30fa172dbe579cf7b1a06594048` lists a 3.50 GB checkpoint under the SAM License. Its model card reports anatomy/tissue macro mask AP **0.1422**, with substantial class variation: liver **0.019**, small intestine **0.000**, and stomach **0.763**. These are author-reported AP measurements, not probabilities of correct organ identification or a local comparison against SAM2. Metadata, licence and inference instructions were inspected; this checkpoint was **not downloaded or run**. The whole-body starter therefore uses the dataset's final expert-reviewed masks and source labels. [Pinned model card](https://huggingface.co/mehmetkeremturkcan/SAM3-Joint-Surgical/blob/1c0c2ed55d46a30fa172dbe579cf7b1a06594048/README.md).

Do not infer an organ's identity from redness or from a SAM mask-quality score. A model proposal can suggest a label; the reviewed organ-to-material assignment is separate provenance. One well-selected, uncontaminated interior patch can be adequate for a color reference even when the whole visible organ cannot be accurately outlined.

## What the newest evidence changes

The December 2025 SAM 3 surgical benchmark finds strong **spatially prompted instrument segmentation** but poor text-prompted surgical semantics. Its EndoVis instrument results should not be quoted as automatic liver/gallbladder recognition evidence. The authors also evaluate SAM 3D separately; this does not make a segmentation mask a calibrated 3D organ reconstruction. [Primary benchmark](https://arxiv.org/abs/2512.07596)

The July 2026 SurgSAM3 paper supports adapting text-prompted masks using a shared tissue/instrument vocabulary. However, the presented CholecSeg8k split lists clip identifiers such as `01_00080` and `01_00240`; the stated procedure does not establish separation by original operation/patient. Its selected class tables and cross-procedure results are not a universal organ benchmark. The paper contains both a code link and future-release wording; the current repository confirms inference code but says trained LoRA weights remain forthcoming. Treat the method as a reproducible training direction to audit, not a deployable checkpoint. [Paper and split description](https://arxiv.org/html/2607.23694v1), [current release state](https://github.com/ChangjingLiu/SurgSAM3)

SurgiSAM2's published performance is useful evidence that domain adaptation helps, with prompts and data conditions stated. Its release page expressly names CholecSeg8k and Endoscapes as CC BY-NC-SA 4.0, m2caiSeg as CC BY-NC 4.0, Dresden as CC BY 4.0, and UreterUD under IEEE DataPort terms. This directly affects checkpoint selection; it is not a hypothetical blanket prohibition on research. [Author's checkpoint notice](https://figshare.com/articles/media/SurgiSAM2_Fine-tuning_a_foundational_model_for_surgical_video_anatomy_segmentation_and_detection/28489961)

## Recommended integration contract

1. Load a source image locally and select the intended scene organ. Preserve source identifier/hash, image dimensions, color encoding, and any resizing transform.
2. Accept an uploaded binary mask or drawn region. Optionally generate/refine it with a box and positive/negative points through SAM 2.1. A classical backend remains available without downloading weights.
3. Display the mask overlay and editable exclusions. Instruments, gauze, blood pools, exposed fat, smoke, shadow and highlights can contaminate the color estimate even inside an organ's silhouette.
4. Compute color statistics from a conservative interior region, showing retained and excluded pixels. Preserve original-image sampling coordinates; do not estimate colors from the colored overlay or a thumbnail.
5. Preview transfer to exactly the selected organ and apply as one reversible history operation. Persist the reviewed target label and segmentation backend separately from the extracted appearance parameters.
6. Mark data-quality diagnostics as diagnostics. Mask model scores, accepted-pixel fraction, contrast and retained area are not calibrated probabilities of correct anatomy.

These steps are a proposed engineering design. They do not require accepting any claim that one uncalibrated RGB image uniquely determines albedo, roughness, subsurface scattering or stiffness. Color matching can be useful while those quantities remain unidentifiable.

## Evaluation needed before claiming semantic automation

- Freeze an allowed organ vocabulary and an **unknown / not visible** output; include photographs where the requested organ is absent.
- Split by original surgical operation/patient and acquisition source, not adjacent video frames or clips. Keep camera, illumination, blood, instruments, smoke and severe occlusion strata visible in results.
- Compare manual patch selection, GrabCut, base SAM 2.1, base SAM 3 and any licensed fine-tune using the same prompt budget. Report mask IoU/Dice, contamination rate in the accepted color pixels, rejected cases and reviewer correction time separately.
- Score organ identity independently from region overlap. An anatomically wrong region with a clean edge is still a wrong assignment.
- For this feature, evaluate the downstream color statistic against an independently reviewed clean-tissue mask, in addition to whole-mask overlap. Stratify errors by lighting; a successful mask does not remove illumination bias.
- Synthetic images can validate pixel coordinates, masking, exclusions, color conversion, history and export. They cannot establish organ recognition on surgical photographs.

## Implemented and executed follow-up

The optional [local adapter](../../services/api/reference_segmenter.py) now runs the official `facebook/sam2.1-hiera-tiny` Transformers checkpoint through explicitly selected SAM 2 image classes. It accepts normalized boxes and positive/negative points, loads only a local safetensors file, rejects incomplete weights, prevents concurrent inference, returns the original-resolution mask and keeps organ identity user-assigned. No model download occurs during a request.

Twenty-one focused tests pass, covering prompt geometry, original-image mask dimensions, invalid input, busy/error cleanup, default/override model discovery, missing local weights and safetensors-only loading. Actual model execution also passed: synthetic ellipse mask IoU **0.9941**, and a real **1920×1080 DRENDS ex-vivo porcine colon** frame segmented in **0.779 s** with the cached model on CPU using four Torch threads. The first synthetic inference including model load took **9.24 s**. These are individual observed timings, not a throughput benchmark. The real image has no independent segmentation truth; its mask has visible holes and marginal islands and requires review. This is a real model integration smoke, not validated human-organ recognition. [Recorded evidence and source attribution](../../artifacts/reference-material/sam2-verification/README.md)

The `reference-segmentation` optional dependency group pins the tested Torch 2.8.0 / Torchvision 0.23.0 / Transformers 4.57.1 combination. The [explicit installer](../../scripts/install_reference_sam2.py) downloads only pinned official public files, verifies exact sizes and SHA-256 digests, and includes the Apache license. The adapter discovers this fixed project checkpoint if installed; `VISCERA_SAM2_MODEL` overrides it. Service startup and image requests never fetch weights. Installation and offline verification commands are in the evidence README.
